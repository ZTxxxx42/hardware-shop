# 五金商贸网站 · MVP 需求初稿

> 版本 v0.1 ｜ 2026-11-07 ｜ 状态：待评审

## 1. 项目定位

面向五金工具、五金配件/辅料的在线商贸网站。同一站点同时服务 **零售** 与 **批发** 两类客户，按客户等级展示不同价格，通过 **在线支付** 完成交易。

## 2. 目标与原则

- **目标**：以最小成本跑通「商品展示 → 下单 → 在线支付 → 订单履约」闭环，快速上线验证。
- **原则**：先做闭环必需（P0），再做体验优化（P1）；明确不做（P2 及以后）以控制范围，避免 MVP 范围蔓延。

## 3. 角色与用户

| 角色 | 说明 | 权限 |
| --- | --- | --- |
| 游客 | 未登录访问者 | 浏览商品、搜索、查看零售价 |
| 注册会员 | 注册/登录的买家，分等级 | 按等级看价、购物车、下单、支付、查订单 |
| 管理员 | 后台运营 | 商品 / 分类 / 价格 / 客户 / 订单管理 |

**会员等级（MVP 固定 3 级，由管理员在后台指定）：**

- 零售客户：默认等级，看零售价
- 批发客户：看批发价
- VIP 客户：看 VIP 价

## 4. MVP 功能清单

### 4.1 前台（买家侧）

**P0（闭环必需）**

- 商品浏览：首页、分类导航、商品列表、商品详情、分页
- 搜索：按商品名称 / 型号 / 关键词
- 价格展示：游客看零售价；登录后按客户等级显示对应价格
- 购物车：加购、改数量、删除、合计（登录后可用）
- 下单：选择收货地址 → 确认订单（商品 / 数量 / 单价 / 总价）→ 生成订单
- 在线支付：微信 / 支付宝，支付回调更新订单状态
- 订单中心：我的订单列表、详情、状态、取消待支付订单
- 账号：注册、登录、退出
- 个人中心：收货地址管理、基本资料

**P1（体验优化）**

- 商品筛选（分类、价格区间、品牌、排序）
- 库存显示与售罄提示
- 商品上下架状态实时反映到前台

### 4.2 后台（商家侧）

**P0（闭环必需）**

- 管理员登录
- 商品管理：增删改查、上下架、多图、规格属性文本、库存数量
- 分类管理：多级分类（至少两级：大类 → 小类）
- 价格管理：按「商品 × 等级」设置价格；支持按等级批量折扣作为快捷辅助
- 客户管理：客户列表、指定客户等级
- 订单管理：列表、详情、状态流转（待支付 → 已支付 / 已取消 → 已发货 → 已完成）、发货
- 支付流水：查看在线支付记录，与订单对账

**P1（体验优化）**

- 库存预警（低于阈值提示）
- 订单导出（Excel / CSV）
- 简易统计看板（销售额、订单量）

## 5. 关键业务流程

1. **下单支付**：浏览/加购 → 结算 → 生成订单（待支付）→ 在线支付 → 支付成功（已支付）→ 商家发货（已发货）→ 确认收货（已完成）
2. **取消 / 超时**：待支付订单可取消；支付超时自动取消（可选实现）
3. **价格取值**：登录客户按等级取价；游客取零售价；购物车与结算时按客户等级实时计算

## 6. 关键假设与待确认

| # | 事项 | 建议 | 待确认 |
| --- | --- | --- | --- |
| 1 | 多规格 SKU | MVP 先做「单品 + 规格属性文本」，不同尺寸/材质不单独计价、不单独计库存 | 是否同意 |
| 2 | 运费 | MVP 先统一运费（可选满额包邮），不做运费模板 | 运费规则 |
| 3 | 会员等级 | 固定 3 级，后台人工指定，不做自动升级 | 等级定义 |
| 4 | 支付渠道 | 微信支付 + 支付宝，直连或聚合接入待定 | 渠道 |
| 5 | 库存 | 简单库存数量：下单扣减、取消/退款回补，不做进销存 | 是否 |
| 6 | 发票 | MVP 不做开票，订单暂不含开票信息 | 是否 |

## 7. 非 MVP（明确不做，后续迭代）

- 优惠券、满减、促销活动
- 商品评价 / 晒单
- 询价 → 报价流程（本期采用购物车直接下单）
- 进销存 / 采购 / 多仓
- 多规格 SKU 独立计价（若第 6 节确认暂缓）
- 发票管理
- 短信 / 邮件通知（可后置）
- 分销 / 返佣、多语言 / 多币种

## 8. 技术方向（待架构阶段确定）

仅记录候选，最终由架构设计阶段确定：前端（Vue / React 或服务端模板）、后端（Node / Python / Java）、数据库（MySQL / PostgreSQL）、部署（云主机 / Docker）。本期单体优先，不做复杂微服务。
