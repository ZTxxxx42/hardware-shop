# 五金商贸网站 · 业务合同

> 本文固化 MVP 的业务规则，是前后端实现与验收的统一依据。以 `backend/app/domain`、`backend/app/services` 实际代码为准。需求背景见 [../MVP需求初稿.md](../MVP需求初稿.md)，架构设计见 [../architecture/架构设计.md](../architecture/架构设计.md)，数据模型见 [../database/schema.md](../database/schema.md)。

## 1. 角色与权限模型

| 角色 | 判定方式 | 权限 |
| --- | --- | --- |
| 游客 | 无 JWT | 浏览分类/商品、搜索；**仅见零售价** |
| 会员 | JWT `role=member` | 游客权限 + **按等级看价** + 购物车 + 下单 + 订单中心 + 地址/资料管理 |
| 管理员 | JWT `role=admin` | 后台商品/分类/价格/订单/发货/支付流水管理；前台以零售身份看价 |

会员等级（固定 3 级，由管理员在后台指定）：

| code | 名称 | 说明 |
| --- | --- | --- |
| `retail` | 零售客户 | 默认等级，取商品零售价 |
| `wholesale` | 批发客户 | 取批发价 |
| `vip` | VIP客户 | 取 VIP 价 |

实现要点：

- JWT 无状态认证，payload 携带 `sub`（user_id）、`role`、`level_code`；`backend/app/core/security.py`。
- 接口级鉴权：`require_member` / `require_admin` / `get_optional_user`（价格接口按登录态动态返回）；`backend/app/core/deps.py`。
- 注册即会员（`role=member`），但**不创建 member_profile**，等级为空 → 价格回退零售价；等级由后台指定。`backend/app/services/auth.py`。
- **已知缺口**：后端暂无「客户管理」管理端点（客户列表、资料编辑、指定等级），后台页面已标注；见 [../api/api-client-mapping.md](../api/api-client-mapping.md)。

## 2. 分级价格规则

- `product.retail_price` 为零售价（基础价）。
- `product_price(product_id, level_code)` 为「商品 × 等级」显式价格，唯一约束 `(product_id, level_code)`。
- 取价逻辑（`backend/app/domain/pricing.py::resolve_product_price`）：
  1. 会员 `level_code` 命中 `product_price` → 取等级价；
  2. 未命中（含等级为空）→ 回退 `retail_price`；
  3. 游客 → 零售价。
- 后台「按等级批量折扣」为快捷操作，**即时展开写入 `product_price` 冗余落库**；下单与展示只读 `product_price`，不运行时计算折扣。
- 购物车价格不落库，`GET /cart`、商品列表/详情均实时取价。
- 商品详情中的 `level_prices`（分级价列表）仅管理员可见，避免会员看到其他等级价。`backend/app/services/catalog.py`。

## 3. 库存规则

- 库存字段 `product.stock`（INTEGER）。
- 可售条件：`product.status == "ON_SALE"`（`backend/app/services/catalog.py::ON_SALE_STATUS`）。
- **下单预占扣减**：`POST /orders` 时校验 `quantity > 0 且 stock >= quantity`，通过后扣减库存。
- **取消回补**：待支付订单取消时，回补订单项对应库存。
- **支付回调不二次扣减**：库存已在下单时预占，回调仅做幂等状态流转。
- 纯规则：`backend/app/domain/inventory.py`；用例编排：`backend/app/services/order.py`。

> 设计取舍：下单即预占扣减，消除「已付款但库存被其他订单抢光」的边界（MVP 无退款机制）；详见 [../api/issues.md](../api/issues.md)。

## 4. 订单状态机

状态枚举（`backend/app/domain/order_state.py`）：

| 状态 | 含义 |
| --- | --- |
| `PENDING_PAYMENT` | 待支付 |
| `PAID` | 已支付 |
| `SHIPPED` | 已发货 |
| `COMPLETED` | 已完成 |
| `CANCELLED` | 已取消 |

合法流转：

```
PENDING_PAYMENT ──支付成功回调──▶ PAID ──商家发货──▶ SHIPPED ──买家确认收货──▶ COMPLETED
PENDING_PAYMENT ──买家取消──────▶ CANCELLED（回补库存）
```

| 动作 | 当前状态 | 目标状态 | 触发端点 | 副作用 |
| --- | --- | --- | --- | --- |
| 下单 | — | PENDING_PAYMENT | `POST /orders` | 校验库存、锁价、预占扣减、创建支付单、清空购物车 |
| 支付成功回调 | PENDING_PAYMENT | PAID | `POST /payment/notify/{channel}` | 记录支付流水、写入 `paid_at` |
| 买家取消 | PENDING_PAYMENT | CANCELLED | `POST /orders/{id}/cancel` | 回补库存、关闭 PENDING 支付单 |
| 商家发货 | PAID | SHIPPED | `PATCH /admin/orders/{id}/ship` | — |
| 确认收货 | SHIPPED | COMPLETED | `POST /orders/{id}/confirm` | — |

非法流转（如 已发货→待支付、已完成→已取消）由领域层状态机拒绝，返回 `INVALID_STATE_TRANSITION`。MVP 不做退款，支付失败保持待支付。

## 5. 关键业务流程

### 5.1 下单支付

1. 会员浏览商品，按等级实时取价展示。
2. 加购：购物车存 `product_id + 数量`，价格不落库。
3. 结算：选收货地址 → 后端校验库存 → 按等级重新计算单价与总额 → 创建订单（待支付）+ 支付单，**预占扣减库存**，清空购物车（同一事务）。
4. 创建支付：调支付网关生成预支付单（MVP 桩实现，联调接入微信/支付宝）。
5. 支付成功：网关异步回调 → 后端验签 + 幂等 → 订单转「已支付」、记录流水 → 应答成功。
6. 商家后台发货 → 「已发货」。
7. 买家确认收货 → 「已完成」。

下单内部顺序（`backend/app/services/order.py::create_order`）：校验地址 → 校验购物车非空 → 逐项校验库存并锁价 → 计算运费/总额 → 创建订单与订单项（扣减库存）→ 创建支付单 → 清空购物车 → 提交事务。

### 5.2 取消

- 仅待支付订单可取消。
- 取消回补订单项对应商品库存；PENDING 支付单转 `CLOSED`。
- 实现：`backend/app/services/order.py::cancel_order`。

### 5.3 发货与确认收货

- 发货：管理员 `PATCH /admin/orders/{id}/ship`，复用 `order_service.ship_order`，状态机约束在领域层。
- 确认收货：买家 `POST /orders/{id}/confirm`。

### 5.4 支付回调与幂等

- 回调路由 `POST /payment/notify/{channel}` **不设登录鉴权，仅验签**（MVP 验签为桩，见 [../api/issues.md](../api/issues.md)）。
- 幂等保证：`payment(order_id, channel)` 唯一约束 + 订单状态机 + 事务。
  - 先查流水，已 `SUCCESS` 直接应答；
  - 订单已 `PAID` 但流水未成功 → 补齐流水后幂等应答；
  - 并发重复回调 → 捕获 `IntegrityError` 回滚后重载幂等应答。
- 实现：`backend/app/services/payment.py`。

## 6. 运费规则

- MVP 统一运费 **0 元**；`backend/app/services/common.py::calculate_freight` 预留 `FREE_SHIPPING_THRESHOLD`（满额包邮阈值，当前为 0，即未启用）。
- 运费模板为后续演进项（见架构设计 7.2）。

## 7. 金额与精度

- 数据库金额统一 `NUMERIC(10,2)`，应用层使用 `Decimal`。
- 接口中金额以**字符串形式的十进制数**返回，单位为元。
- 金额字段：`retail_price`、`product_price.price`、`order.product_amount/freight_amount/total_amount`、`order_item.price/subtotal`、`payment.amount`。

## 8. 关键约束汇总

| 约束 | 位置 | 目的 |
| --- | --- | --- |
| `user.username` 唯一 | `user` 表 | 登录唯一 |
| `order.order_no` 唯一 | `order` 表 | 订单号唯一（`SO` 前缀 + 时间戳 + 随机数） |
| `product_price(product_id, level_code)` 唯一 | `product_price` 表 | 同商品同等级仅一条价格 |
| `payment(order_id, channel)` 唯一 | `payment` 表 | 支付回调幂等 |
| 收货地址快照 4 列 | `order.receiver_*` | 下单固化，防地址后续变更影响历史订单 |
| 订单项名称/单价快照 | `order_item.product_name/price` | 防商品改价影响历史订单 |
