# 五金商贸 MVP · 部署说明

> 本文给出后端、两个 Web 前端、微信小程序的本地运行与部署步骤。架构拓扑与运维要求见 [../architecture/架构设计.md](../architecture/架构设计.md) 第 6 节。仓库已提供 `backend/Dockerfile`、`docker-compose.yml`、`deploy/nginx.conf` 等容器化文件，Docker 部署方案见第 4 节。

## 1. 后端（FastAPI + PostgreSQL）

### 1.1 环境要求

- Python 3.13（架构设计定版，见 CHANGELOG）
- PostgreSQL 16（数据库名默认 `hardware_shop`，连接串见 `.env`）
- 依赖见 `backend/requirements.txt`

### 1.2 本地运行

```bash
cd backend

# 1) 创建虚拟环境并安装依赖
python -m venv .venv
# Windows: .venv\Scripts\activate；Linux/macOS: source .venv/bin/activate
pip install -r requirements.txt

# 2) 准备环境变量
cp .env.example .env   # 按需修改 SECRET_KEY / DATABASE_URL / CORS_ORIGINS

# 3) 建表
alembic upgrade head

# 4) 填充种子数据（可重复执行）
python -m scripts.seed

# 5) 启动（开发）
uvicorn app.main:app --reload --host 0.0.0.0 --port 8000
```

启动后可访问：

- 健康检查：`GET http://localhost:8000/healthz`
- OpenAPI 文档：`http://localhost:8000/docs`（FastAPI 自动生成）

### 1.3 生产运行要点

- 生产关闭 `--reload`，建议 `uvicorn app.main:app --host 0.0.0.0 --port 8000 --workers <N>`，外层由 Nginx 反代并终止 TLS。
- 关键环境变量（`backend/.env`）：`DEBUG`、`SECRET_KEY`（必须改）、`DATABASE_URL`、`CORS_ORIGINS`（JSON 数组）、`WECHAT_PAY_API_V3_KEY`、`ALIPAY_APP_PRIVATE_KEY`（支付联调后填写）。
- 数据库备份：PostgreSQL 每日 `pg_dump`；`.env` 与证书需一并备份。

## 2. Web 前端（Vite build）

买家端 `frontend/shop-web/` 与管理端 `frontend/admin-web/` 构建方式一致。

```bash
# 买家端
cd frontend/shop-web
npm install
cp .env.example .env.production   # 配置 VITE_API_BASE_URL 为后端公网地址
npm run build                      # 产物在 dist/

# 管理端
cd frontend/admin-web
npm install
cp .env.example .env.production
npm run build                      # 产物在 dist/
```

Nginx 托管要点（两个 SPA 均为 history 路由）：

```nginx
server {
    listen 443 ssl;
    server_name shop.example.com;   # 按实际域名

    root /var/www/shop-web/dist;
    index index.html;

    location / {
        try_files $uri $uri/ /index.html;
    }

    location /api/ {
        proxy_pass http://127.0.0.1:8000;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
    }
}
```

管理端同理，可用独立域名或子路径挂载（子路径需同步调整 Vite `base` 与路由 `base`）。

## 3. 微信小程序（uni-app）

### 3.1 编译

```bash
cd frontend/mp-shop
npm install

# 微信小程序产物（输出到 dist/build/mp-weixin）
npm run build:mp-weixin

# H5 预览/构建（开发联调用）
npm run dev:h5
npm run build:h5
```

### 3.2 环境与 API 地址

小程序通过 Vite 环境变量 `VITE_API_BASE_URL` 区分环境：

| 文件 | 用途 |
| --- | --- |
| `.env.development` | 开发/H5 联调，默认 `http://127.0.0.1:8000` |
| `.env.production` | 构建占位，默认 `https://api.example.com` |
| `.env.production.local` | 真实生产 HTTPS 域名，本地私密填写，**不要提交** |
| `.env.local` / `.env.*.local` | 本地私密覆盖文件，已被 `frontend/mp-shop/.gitignore` 忽略 |

真实 AppID、AppSecret、商户号、商户密钥与证书均只放在后端私密环境或平台配置中，禁止写入仓库。`src/manifest.json` 的 `mp-weixin.appid` 当前为 `__WECHAT_MP_APPID__` 占位，构建与真机前按环境替换为真实 AppID。

### 3.3 开发者工具与真机边界

1. 打开「微信开发者工具」，选择「导入项目」。
2. 目录选择 `frontend/mp-shop/dist/build/mp-weixin`。
3. AppID 填入真实小程序 AppID（或使用测试号，仅限开发验证）。
4. 开发调试期可在「详情 → 本地设置」勾选「不校验合法域名」，只用于本地开发；真机预览、体验版与正式版必须使用小程序后台配置的合法域名。

环境边界：

| 环境 | API 域名要求 | 说明 |
| --- | --- | --- |
| H5 本地开发 | `http://127.0.0.1:8000` | 端口 5175；后端 `CORS_ORIGINS` 必须包含 `http://127.0.0.1:5175` 与 `http://localhost:5175` |
| 微信真机调试 | HTTPS + 备案域名 | 小程序不支持 IP/HTTP；测试环境也要配置合法域名或临时关闭校验 |
| 测试/预发 | 独立 HTTPS 域名 | 与正式环境域名、数据库隔离，避免串单 |
| 正式环境 | 备案 HTTPS 域名 | 微信后台配置 `request` 合法域名；支付、隐私保护指引随平台审核同步确认 |

### 3.4 上线要点

| 项 | 要求 |
| --- | --- |
| 请求域名 | 小程序后台配置 `request` 合法域名为后端 HTTPS 域名；小程序不支持 IP/HTTP，必须 **HTTPS + 备案域名** |
| 微信登录 | 已接入 `uni.login` → `POST /api/auth/wechat/login`；后端未配置微信 AppID/AppSecret 时返回不可用，前端提示「微信登录暂未开通」，账号密码登录保留兜底 |
| 账号注销 | 已接入 `POST /api/member/account-deletion`；页面仅展示 PENDING 申请状态，不在客户端即时删除 |
| 微信支付 | 支付网关仍为桩实现，前端「去支付」仅提示「支付暂未接入」；无商户证书不得伪造支付成功 |
| tabBar 图标 | 已内置 8 张 PNG（见素材清单），激活态已统一为工业橙 |
| 版本 | `src/manifest.json` 维护 `versionName`/`versionCode` |

### 3.5 端口说明

- 小程序 H5 开发端口为 `5175`（`src/manifest.json` 的 `h5.devServer.port`），与 shop-web（5173）、admin-web（5174）互不冲突。
- 后端本地开发默认 `http://127.0.0.1:8000`，需确认 `.env` 的 `CORS_ORIGINS` 同时包含 5173、5174、5175 的 localhost 与 127.0.0.1 地址。

## 4. Docker Compose 部署（单机）

已落地容器化方案，拓扑与架构设计第 6 节一致：`nginx` + `api` + `postgres` 三容器，密钥经 `.env` 注入、不写镜像。

| 文件 | 作用 |
| --- | --- |
| `backend/Dockerfile` | 后端镜像：Python 3.13-slim + uvicorn；非 root 运行；内置健康检查 |
| `backend/docker-entrypoint.sh` | 启动前执行 `alembic upgrade head`（幂等），可选填充种子数据 |
| `docker-compose.yml` | 编排三容器、数据卷、健康检查与依赖顺序 |
| `deploy/nginx.conf` | 静态托管两个 SPA + 反代 `/api` + gzip/缓存 + TLS 注释模板 |
| `.env.example`（根目录） | Compose 环境变量模板（DB 口令、`SECRET_KEY`、`CORS_ORIGINS` 等） |
| `.dockerignore` / `backend/.dockerignore` | 排除 `node_modules`、`dist`、`.env`、`__pycache__` 等 |

### 4.1 一键启动

```bash
# 1) 配置环境变量(生产务必修改 SECRET_KEY 与 POSTGRES_PASSWORD)
cp .env.example .env

# 2) 构建两个 Web 前端产物(admin-web 需以 /admin/ 子路径构建,见 4.3)
cd frontend/shop-web && npm install && npm run build && cd ../..
cd frontend/admin-web && npm install && npm run build && cd ../..

# 3) 启动
docker compose up -d --build
```

启动后：

- 买家端：`http://<主机>/`
- 管理端：`http://<主机>/admin/`
- API：`http://<主机>/api/...`（Nginx 反代到 `api:8000`）
- API 健康检查：容器内 `http://api:8000/healthz`

### 4.2 首次初始化与种子数据

`api` 容器启动时自动执行 `alembic upgrade head`（等待 `db` 健康后才启动）。种子数据默认不填充；首次联调可任选其一：

```bash
# 方式一:容器内执行(幂等)
docker compose exec api python -m scripts.seed

# 方式二:首次启动即填充
SEED_DATA=true docker compose up -d api
```

### 4.3 管理端子路径挂载前提

`deploy/nginx.conf` 将管理端挂在 `/admin/`。SPA 资源路径由 Vite `base` 与路由 `base` 决定，当前 admin-web 代码默认 `/`，子路径部署前需在构建侧配置（属前端构建配置，非本 DevOps 交付范围）：

- `frontend/admin-web/vite.config.ts`：`base: '/admin/'`
- `frontend/admin-web/src/router/index.ts`：`createWebHistory('/admin/')`

未配置时 `/admin/` 下的静态资源会 404。如不想改前端配置，可将管理端改挂独立域名/端口，在 nginx 另建 server 块。

### 4.4 生产环境 API 地址

容器化部署建议走同源（前端由 Nginx 托管，`/api` 由 Nginx 反代）。构建前端时设置：

```bash
# shop-web 与 admin-web 均适用;VITE_API_BASE_URL=/ 会生成相对路径,经 Nginx 反代同源访问
VITE_API_BASE_URL=/
```

或填写完整 HTTPS 域名：`VITE_API_BASE_URL=https://shop.example.com`。

### 4.5 HTTPS / TLS 启用

1. 证书放入 `deploy/certs/`（如 `fullchain.pem`、`privkey.pem`）。
2. 取消 `docker-compose.yml` 中 `nginx` 的 443 端口与 `./deploy/certs` 卷挂载注释。
3. 取消 `deploy/nginx.conf` 中 443 server 块与 80→443 跳转块注释，替换为实际域名。
4. `docker compose up -d nginx` 生效；支付回调需公网备案域名 + HTTPS。

### 4.6 环境变量说明

| 变量 | 默认值 | 说明 |
| --- | --- | --- |
| `POSTGRES_DB` | hardware_shop | 数据库名 |
| `POSTGRES_USER` | postgres | 数据库账号 |
| `POSTGRES_PASSWORD` | postgres | 数据库口令（生产必改） |
| `DEBUG` | false | 后端调试开关 |
| `SECRET_KEY` | please-change-me | JWT 签名密钥（生产必改） |
| `ACCESS_TOKEN_EXPIRE_MINUTES` | 1440 | JWT 有效期（分钟） |
| `CORS_ORIGINS` | localhost 白名单 | JSON 数组；生产填实际 HTTPS 域名 |
| `WECHAT_PAY_API_V3_KEY` | 空 | 微信支付 APIv3 密钥（联调后填写） |
| `ALIPAY_APP_PRIVATE_KEY` | 空 | 支付宝应用私钥（联调后填写） |
| `SEED_DATA` | false | 启动时是否填充种子数据 |
| `HTTP_PORT` | 80 | Nginx 宿主机 HTTP 端口 |

`DATABASE_URL` 由 Compose 依 `POSTGRES_*` 拼装为 `postgresql+psycopg://<USER>:<PASSWORD>@db:5432/<DB>`，无需手动填写；若口令含 `@ : /` 等特殊字符需先 URL 编码。

### 4.7 常用运维

- 迁移：容器启动自动执行；手动执行 `docker compose exec api alembic upgrade head`。
- 备份：`docker compose exec db pg_dump -U postgres hardware_shop > backup.sql`。
- 停止/重建：`docker compose down` 保留数据卷；`docker compose up -d --build` 重建（数据卷 `postgres_data` 持久化）。
- 日志：`docker compose logs -f api nginx`。
